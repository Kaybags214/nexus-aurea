# Check 1 — Pairing

Establish, before anything else, that this package and the prior report describe the **same
shipment**. Everything downstream is meaningless otherwise.

- [ ] Prior report located, and its path recorded
- [ ] Shipper matches
- [ ] Consignee matches
- [ ] AWB number matches — or the prior report's finding was that it was wrong, in which case
      the change is expected and is itself a closure to assess
- [ ] Commodity and UN numbers match
- [ ] Document types in this package correspond to those reviewed before

## When the prior report cannot be found

**Stop.** This is not a re-review, and it must not be billed as one. Either locate the prior
report, or run the appropriate first-review skill and say plainly that this was reviewed as a
new package.

Do not reconstruct the prior findings from the corrected document. You would be inventing a
history and then marking it closed.

## When the pairing is partial

A client may return **one corrected document** out of a package of five. That is normal.

- [ ] Record which documents were resubmitted and which were not
- [ ] Findings on documents that were **not** resubmitted stay **open** — an unreturned document
      is an uncorrected document, not an assumed one

Say this explicitly in the report. A client who resubmits the declaration and not the AWB may
believe the whole package was re-reviewed.

## Record before moving on

- Prior report path and date
- Its verdict
- Its finding counts: Critical, Major, Minor
- Which documents are in this package

Check 2 works from that list.
