# Check 4 — Carry-forward

Two things from the first review must survive into this one, or the client is misled by
omission.

## 1. The unverified list

Every report carries an `unverified` array in its sidecar: checks the run could not confirm —
a packing instruction limit with no DGR copy to hand, a marking not visible in the photograph, a
state variation with no source.

**Those items were never resolved.** They were not findings and they were not clearances. If
this report is silent on them, a client reasonably concludes they went away.

- [ ] Every unverified item from v1 is listed again
- [ ] Each is marked: **still unverified**, or **now verified** with what verified it
- [ ] Anything now verifiable because the corrected package supplies the missing information is
      verified and stated

## 2. Not-performed checks

If v1 recorded a check as **not performed** — commonly *"agreement with the AWB: no AWB
submitted"* — say whether this package changed that.

- [ ] Checks not performed in v1 are listed
- [ ] Each is marked performed now, or still not performed and why

A client who sends the missing AWB has bought that check being run. A client who does not should
be told it still has not been.

## What the client gets

The re-review report closes with three lists, and a client should be able to read only these:

1. **Closed** — findings resolved, with what closed them
2. **Still open** — findings not closed, plus any new ones from check 3
3. **Still unverified** — what nobody has confirmed yet, and what would confirm it

The third list is the one most likely to be dropped and the one most likely to matter later. It
is the difference between a finding that can be defended and one that cannot.
