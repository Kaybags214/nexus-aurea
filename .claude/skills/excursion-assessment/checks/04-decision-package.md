# Check 4 — Assemble the quality decision package

The deliverable. Not a verdict on the product — the evidence set a QP needs to make one.

- [ ] Product name, strength, presentation
- [ ] **Lot / batch number**, cross-checked against the CoA, packing list and invoice
- [ ] Quantity affected
- [ ] Labelled storage condition and its source (check 1)
- [ ] Logger identity, calibration status and placement (check 2)
- [ ] Full excursion table plus cumulative total (check 3)
- [ ] Complete time-temperature record attached, not summarised away
- [ ] Lane and custody chain — who held the shipment during each excursion
- [ ] Packaging configuration and its qualified duration, where known
- [ ] Any prior excursions on this lot

## What to hand over, and to whom

State plainly: **this package goes to the MA holder or QP for a release decision.** Name that
as the next action in the report.

## What must not appear in this report

- "Product is unaffected" / "within acceptable limits" / "safe to release"
- A stability-budget calculation presented as a conclusion
- An MKT figure offered as a pass
- Any wording a reader could mistake for release authorisation

If the requester pushes for a fit-for-use answer, the answer is that this assessment does not
provide one and cannot be made to. Give them the package instead.

## Notification

- [ ] Note whether the consignee, MA holder and QA have been notified, and when
- [ ] Where notification has not happened, that is itself a finding — most quality agreements
      set a notification clock that starts at discovery
