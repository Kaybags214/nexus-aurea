## 1. How work crosses between tools

More than one assistant works on this repository — Abacus builds content, Claude Code reviews
and hardens it. They share nothing but this repository.

- **A file that is not committed does not exist.** Describing a file in a chat transcript is
  not the same as creating one. Neither tool can see the other's workspace, local disk, or
  scratch files.
- **Hand off by committing and pushing**, then say which branch. Do not paste a file and assume
  it landed.
- **State what was actually done, not what was intended.** "8 fixes applied" must mean eight
  fixes are in a commit.

*Evidence: v1.0.1 was reported complete with 8 fixes; the files never reached the repo. This
file was believed to exist and did not.*

## 2. Verification discipline — non-negotiable

- **Never record a verification that did not happen.** No "verified against", "current as of",
  or "checked on" unless someone actually checked.
- **Primary sources are currently unreachable** from the Claude Code environment:
  `ecfr.gov`, `govinfo.gov` and `law.cornell.edu` are blocked by network egress policy. Any
  citation work depends on a human pasting the source text.
- A finding that cannot be checked is **Unable to Verify** — never Pass, never Fail, regardless
  of how confident the reviewer is.
- **Never invent a regulation, shipping name, weight, temperature, or approval.** If it is not
  in a source in this repo, it does not go in a deliverable.

## 3. Findings vocabulary

Every finding carries exactly one status:

| Status | Meaning |
|---|---|
| Pass | Present, correct, consistent with the cited regulation |
| Fail | Missing, incorrect, or inconsistent — flag for human review |
| Warning | Present but anomalous or ambiguous — human verification required |
| Unable to Verify | Document or data not provided, not legible, or source unreachable |
| Not Applicable | Rule does not apply to this shipment type, mode, or material |

Every finding cites a specific regulatory section. "GDP guidelines" and "Nexus Aurea audit
scope" are not citations.

## 4. Output discipline

- **All findings are DRAFT.** Human review before any action.
- **Never issue "clearance", "approved", or "safe to ship".**
- Findings identify discrepancies and missing data. They do not authorise anything.

## 5. Document control

Any document that generates client-facing findings is a controlled document and needs:

- A document number, version, and change history
- A named author, technical reviewer, and **approver**
- An effective date, or an explicit "NOT EFFECTIVE — not released"
- A stated review cycle

An unapproved document producing regulated findings is itself an audit finding.

## 6. Source of record

Where a document exists in two formats, exactly one is authoritative and the other is
**generated** from it. Never maintain both by hand — they will diverge, and a divergence at the
same version number is undetectable to a reader.

Current example: `dgr/02-49cfr/nexus_aurea_cfr_library.json` is the source of record;
`nexus-aurea-cfr-library.md` is generated by `tools/build_library.py`; `--check` fails on drift.
