Architecture reference — corrected edition

Four parts,
three levels each

ARMS is not four layers. It is a 4 × 3 grid — each part has a level that works today, a level that scales, and a level where the system runs without you. Build order is bottom-up and starts with Skills, because skills compound into everything else.

What this page corrects

  • Order. The first version put Memory at the foundation. Skills comes first.
  • Shape. The first version drew four flat layers and missed the three levels per part entirely.
  • Applications. Defined here previously as the dashboard for non-technical users. It actually means connectors — CLI, API or MCP — and the micro-apps you build when none exists.
  • The command centre is not part of ARMS. It is a bonus layer, and the guide puts it at 20–30% of the value.
  • The per-skill learnings.md is ours, not theirs. It appears nowhere in the guide. Kept because it earns its place, but it is our convention.

Your workspace and context. The symptom to watch: retrieval slows and tokens climb as clutter grows.
Done whenA brand-new session finds the right file through the routers on the first hop.
L1

Point the agent at one folder and work there. Fine until the files pile up.

Done

Router files, not neat folders

Agents want a map, not tidiness. A master router names your areas and points each to its own one-page index.

Biggest gap

A visual second brain

One local page showing the workspace as a searchable, living map of how files connect.

Not started

Scheduled work — in practice, a prompt the agent sends itself at a time you set.
Done whenAt least one piece of real work ships on schedule with your computer off.
L1

Local routines

Drafted in natural language, output lands where you will see it. Only runs while the machine is on.

Done

L2

Always-on, with its own machine

A small cloud box so routines fire with the laptop closed — and Syncthing so both sides see the same files.

Not started

L3

The whole agent in the cloud

Agent installed on the cloud machine, all context there, no syncing at all.

Not started
Guide’s own note: file security is the hard part; L2 gets the same result today.
AApplicationsPart 4
What your agent can actually reach. Connectors come as a CLI, an API, or an MCP server.
Done whenThe apps you live in are reachable, and one tool you built yourself is part of your week.
L1

Browse the catalog and connect the obvious

Email, calendar, drive. Fine to start, but hand-browsing is not the efficient way in.

Done
Gmail, Drive, Calendar, GitHub, Alpha Vantage and Crypto.com are live. Drive is how the guide reached this session.
L2

Have the agent search

Agent hunts official connectors first, then community ones; shortlists, you pick, it vets the code.

Not started
Worth pointing at carrier and forwarder tooling — tracking, rate, and acceptance systems.
L3

Build your own connectors and apps

When nothing exists, build it: a small CLI, or a micro-app for a job you do weekly.

Partly there
The compliance-auditor n8n webhook is exactly this — a self-built intake for a job with no off-the-shelf tool.

The bonus layer

the command centre — deliberately not part of ARMS

“This layer is only 20 to 30% of the value — but it is the part you see all day… The look is a skin; ARMS underneath is the product.”

ARMS — The Agentic OS Guide, page 13
One page, one addressSame local address daily, survives a restart. If it is not always there, you stop opening it.
Show, do not storeThe page is a window. Artifacts stay files; truth never lives in the dashboard.
Every widget earns its placeGlanceable summaries and one-click actions. Stop looking at a widget, delete it.
Artifacts one click awayA section listing what the agents made recently, so review is not folder-hunting.
The second brain is the centrepieceMemory L3 links from the middle of the page.
Start with three widgetsShip small, grow one prompt at a time.
Restyle freelyThe same skeleton wears any brand — yours, or a client’s.
